三、 明確定義兩大人類角色規範 (Roles & Responsibilities)

徹底區分「業務經營」與「知識架構」，讓人與 AI 各司其職，落實 Human-in-the-Loop 安全閉環

角色 1 • 業務決策 Business Manager

👤 業務管理者 / 營運主管

適合擔任人選：總務主管、廠務處長、ESG 永續經理、大樓/農場資產營運主管。

核心職責清單：

  • 1. 自然語言動口下目標：使用白話提出營運要求（如契約容量壓低、會議室預冷、自動灌溉維持含水）。
  • 2. 補齊業務情境資訊：回應 Task Agent 主動提出的業務問題（如開會人數、品種特性）。
  • 3. 策略審核與一鍵核准：檢視效益模擬預測報告（省電率、成本、舒適度），按下一鍵核准放行。
  • 4. 固化長期自動化規則：成效優異時，授權將任務保存為長期例行排程。
🔒 系統操作邊界：純業務與營運視角，零技術門檻，完全不接觸代碼、API 規格、通訊協定或硬體接線。
角色 2 • 知識架構 Building Knowledge Architect

👤 建築語意架構師

適合擔任人選：弱電/BMS 系統整合工程師 (SI)、BIM 建模師、物聯網機電架構師。

核心職責清單：

  • 1. 建立空間情境（Context）：對照 CAD/BIM 定義空間層級、用途、西曬方位與服務拓撲。
  • 2. 為 IoT API 標註脈絡：將 Gateway 冰冷代碼（DEV_001）綁定到實體會議室或植栽盆。
  • 3. 校準設備語意（Semantic）：定義物理量、測量單位（% VWC, kW, °C）、合理邊界與操作限制。
  • 4. 回應 AI 大腦主動探詢：當 Task Agent 發現設備缺空間歸屬時，及時標註補充，賦予空間靈魂。
🔒 系統操作邊界：專注物理空間拓撲與設備語意的精確性，不負責日常業務運營決策。
比較維度 角色 1：業務管理者 / 營運主管 角色 2：建築語意架構師
關注核心 節能效益、生產產量、電費成本、營運安全 空間拓撲、設備對應、物理量語意、資料完整性
系統輸入 自然語言目標、情境確認、一鍵核准指令 CAD/BIM 空間定義、API 空間標籤、物理邊界規則
技術門檻 完全無技術門檻（自然語言對話介面） 需具備建築空間識圖、弱電點位與物聯網理解能力
參與時機 日常營運、隨時下達目標、審核高風險任務 系統初期建置、空間/設備異動、回應 AI 語意缺失探詢

四、 IoT API：將實體設備轉換成 AI 可理解的能力

IoT API 整合操作介面、語意與空間脈絡，讓 AI 正確發現與調用設備

1

API：操作介面 (Action)

描述設備可以執行什麼操作、如何取得資料。如：read_soil_moisture()、turn_on_pump()、set_vrv_temp()。統一多元底層通訊協定。

2

Semantic：語意描述 (Physics)

說明「這個設備數據代表什麼物理意義」。包含測量對象、物理量（% VWC、kW、°C）、合理數值範圍與機械操作限制，防止 AI 指令失控。

3

Context：情境描述 (Space)

說明「這個設備位於何處、服務什麼情境」。定義空間層級（12F 董事長辦公室 / 3 號番茄盆）、西曬方位、散熱慣性與上下游關聯管線。

五、 三種 Agent 的角色分工與按需掛載機制

分層負責對話、任務規劃與設備智能，實現資源效益最大化

Agent 1 • 常駐

使用者對話 Agent

負責與業務管理者互動。理解自然語言需求、維護跨會話長期對話記憶、掌握使用者偏好，並決定何時建立與委派 Task Agent。

Agent 2 • 長期任務

Task Agent (任務核心)

針對特定目標動態建立。具備任務專屬記憶，負責檢索 IoT API Registry、組裝跨設備能力、協商動態 Event 訂閱，並在收到事件後持續調適策略。

Agent 3 • 按需掛載

IoT API Agent Shell

附加在 IoT API 上的輕量智能外殼。僅在 Task Agent 前來協商需求時才動態掛載，載入設備記憶與 Semantic/Context，建立 Event 規則後即可卸載！

⚡ Agent Shell 的三態生命週期（資源極致優化）

狀態一：待命 (Standby)

IoT API 正常提供，Agent Shell 未掛載。零 AI Token 與算力消耗。

狀態二：智能互動 (Active)

Task Agent 前來，Shell 瞬間掛載！載入記憶、推理狀態、協商並註冊動態 Event。

狀態三：卸載監控 (Unloaded)

Shell 釋放卸載，但設備記憶與已註冊 Event 持續由底層輕量引擎常駐監控！

七、 供另一個 AI 深入研究的 8 大方向

協同研究基準
1. IoT API 標準化描述

以 OpenAPI / JSON-LD / Brick Schema 標準化定義 API + Semantic + Context。

2. 語意圖譜與檢索

Task Agent 如何藉由向量化與 Graph Query 毫秒級定位合適設備。

3. Agent Shell 狀態機

掛載、記憶加載、推理協商、事件委派與卸載之標準狀態轉移生命週期。

4. 設備專屬記憶結構

如何結構化持久存儲設備的長期運行日誌、異常模式與老化補償參數。

5. 輕量化 Event 引擎

在邊緣端 Gateway 旁高效率執行複雜複合條件比對，不佔 LLM 算力。

6. 跨 Agent 通訊規範

Task Agent、對話 Agent 與 Agent Shell 間的標準 JSON/gRPC 訊息通訊格式。

7. 長效任務容錯與恢復

伺服器重啟或網路斷線時，長週期自主 Task Agent 的狀態快照與無損恢復機制。

8. 安全互鎖防呆 (Guardrails)

防止 AI 自主決策引發設備燒毀或工安跳電的物理硬性防呆規則庫。
