步驟 1 · 奠定標準基石

1. IoT 變 API 化 ➔ 封裝為「IoT API 物件」（打破硬體品牌碎片化壁壘）

核心重點：一個實體 IoT 有多個 API，但 API 化後整體聚合封裝為單一「IoT API 物件」，具備狀態屬性與多個操作方法

主管白話：整台設備被打包成標準的軟體物件，隨調隨用！

步驟 3 · 敏捷空間載體

3. 空間 Block Context 建立（可有可無・按需啟用）

步驟 4 · 主動智慧外殼

4. 掛載 Agent Shell，主動記憶對主 Agent 對話

給被動 API 套上外殼：擁有短期任務記憶、把被動化為主動事件、協商完立即卸載節省伺服器記憶體

主管白話：設備變聰明會主動通風報信，交待完任務外殼就退場，不佔資源！
狀態 1

待命 (Standby)

Shell 未掛載，底層設備正常運作，算力開銷 = 0。

狀態 2 · 協商中

智能外殼 (Active Shell)

• 主觀記憶：「VIP預冷中，禁止降頻」
• 建立事件：替被動API建立定時叫醒通知
• 智慧快取：「剛查過，不花錢打外部API」
狀態 3

卸載監控 (Unloaded)

協商完畢 Shell 卸載釋放記憶體；條件觸發時精準喚醒主 Task Agent！

EXECUTIVE FAQ

主管最在意的 3 大問題直球對決

Q1：系統會不會很吃 AI 算力？

不會。 Step 2 結構情境查表免 AI；Step 4 Agent Shell 協商完立刻卸載，95% 時間底層事件引擎在跑，地端小主機就能跑！

Q2：換設備或新廠房要不要重寫？

完全不用。 Step 1 設備 API 化，Step 3 空間像樂高積木按需增減，即插即用，不用重繪複雜 CAD 圖。

Q3：AI 會不會亂開關設備引發事故？

絕對不會。 Agent Shell 內建硬性安全護欄，重大調度透過 Generative UI 必須由主管一鍵核准才落地。
