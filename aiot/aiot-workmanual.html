一、 系統落地兩大核心準則：開放彈性掛載 ＋ 極簡 IoT 健康監控

避免發展成笨重寫死的傳統管理後台，保持核心純粹與無限擴充彈性

Core Design Boundaries
準則 1 • 無限擴充彈性 Pluggable Capability Registry

開放式能力與演算法插件底座（不綁死固定 6 點）

系統絕不寫死為「6 個孤立的節能功能頁」。所有專用數值／機器學習演算法（MPC、焓值運算、Kalman+Fuzzy、Deep RL、C-TimeGAN、XGBoost，乃至未來第 7、第 8 個冰機群控、儲能調度、智慧照明模型）全部封裝為標準 API + Semantic + Context 插件隨插即用。首批 6 點需求只是驗證此彈性底座的「首批標竿任務配方」。

準則 2 • 極簡基礎維運 BOS Gateway Health First

基礎管理唯留「BOS Gateway 接入之 IoT 是否正常」

不重造工單、排班、人事財務等外圍系統（需要時一律以 MCP 外部掛載）。基本管理精準聚焦生命線：即時監控 BOS Gateway 通道心跳、點位連線存活、資料品質（有無卡死 Frozen／超界）與控制讀回確認（Read-back）；異常點位即時亮燈並自動隔離 AI 控制，確保 AI 絕不依據壞數據誤判。

工作台 ① 落點：IoT API Object ⟷ 實體設備 ＆ IoT Shell

BOS Gateway 接入與 IoT API Object 建構台

  • 概念圖實作位置：直接作用於 IoT API Object (實體設備物件化) 節點與其對接 🏢 實體現場設備 的橋接線上，並將即時屬性與健康狀態同步至 ③ IoT Agent Shell。
  • 物件化實例建構：將實體冷氣/電表封裝為單一物件實體，綁定 Properties（即時遙測值）與 Methods（控制方法群，如 .set_temperature()）。
  • 點位匯入與安全邊界：批次匯入 BOS 點位清冊，定義物理安全上下限（如 18~28°C、最短啟停間隔 5 分鐘），異常點位自動隔離保護。
工作台 ② 落點：Block 空間實體容器 ＆ Structural Context

Block 空間拓撲與屬性畫布

  • 概念圖實作位置：建構 Block 空間實體容器 節點，並寫入 IoT API Object 的 Structural Context（結構情境）。
  • 幾何拼裝與空間標籤：拖拉完成樓層堆疊（Stack）、房間內裝（Nest）與走廊相連（Connect）；標註西曬熱慣性、人流變動特性、以及 DR 需量分區（🔴 核心保護區 vs. 🟢 彈性緩衝區）。
  • 物件拖拉裝載與共軛迴路：把確認健康的 IoT API Object 拖進 Block 空間容器內裝，並指定跨設備共軛關係（如哪台 ERV 與哪幾台 VRV 共用供氣區）。
工作台 ③ 落點：能力外殼 (Agent Shell) ＆ 外部演算法插件

開放式能力外殼與演算法掛載中心 (Pluggable Registry)

  • 概念圖實作位置：作用於為 IoT API Object 掛載專屬的 Agent Shell 智慧外殼（車輛配司機模式），並擴充外部服務與演算法插件。
  • 意圖溯源與因果記錄：Agent Shell 在此註冊參與哪些業務 Flow，並永久長存「當初為什麼要建立這些排程與事件（決策由來）」，支援 XAI 可解釋性。
  • 演算法即插件（無限擴充彈性）：在 Everything as Object 架構下，無論是氣象／電價 API、行事曆 MCP，或是任意專用 AI 演算法容器（MPC、焓值、Kalman+Fuzzy、Deep RL、C-TimeGAN、XGBoost 及未來第 7~N 種新模型），皆以標準物件方法介面註冊掛載。
工作台 ④ 落點：雙角色商談連線 ＆ Task Agent 核准防線

L0～L4 控制權限與生成式 UI 樣板台

  • 概念圖實作位置：橫跨 👤 架構師 --- 👤 業務管理者 商談線，以及 ② Task Agent ➔ ❼ 呈報決策卡 / ❽ 一鍵核准 的治理閘門。
  • L0～L4 分級治理防線：按區域設定 L0 唯讀觀察 ➔ L1 僅提建議 ➔ L2 主管核准寫回 ➔ L3 白名單邊界自治（並支援 L4 緊急切回既有 BAS）。
  • UI 樣板共創與全棟複製：與業務主管商談定稿卡片樣板（JSON Schema），以 Block 為變數一鍵批次套用至全棟標準樓層。

樣板 C • 變更前無風險驗證

虛擬試車驗收報告卡

樣板 D • 診斷與安全防線
